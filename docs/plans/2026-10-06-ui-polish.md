# Production dashboard UI refinement

## Mounted baseline

Reviewed all twelve production routes in compiled omp 18.6.1 against real local history, including a 40-column frame. Existing workflows work, but the body frequently reads as an unaligned text dump rather than a dashboard:

- Overview places the latest-request list ahead of complete-range metrics and the activity graph.
- Models/Costs/Tools repeat full-width chart baselines, show unformatted point values (including floating-point cost tails), and push summaries below legends.
- Request/provider/tool tables concatenate fields, so long identity/path columns hide useful quantitative values.
- Long instructional prose consumes several rows ahead of the data; focus is often only named in prose.
- Projects repeats three empty-table messages when its temporary-folder filter excludes all rows; Gain mixes an honest empty notice with a zero-event source row.
- Trace root titles can be blank; passive Frustration has useful measured rates but weak visual hierarchy and a sparse chart.

## Design decisions

1. Match omp's initialized theme, text weights, selection background and symbol preset. No browser hex palette, dependency on Nerd Font chart marks, decorative metrics or paid calls.
2. Put complete/scoped metric cards near the top: high-signal figures, explicit units, compact caveats and actual trends where available. Reuse the existing band tile/table grammar rather than create another card system.
3. Standardize production time-series plots by reusing the existing provider/Gain chart renderer in the shared chart namespace. Provide compact scale/time labels, consistent series colors, bounded viewports, clear gaps and selected-point inspection. Keep the pure IR/probe renderer separate.
4. Use measured aligned tables with identity-first column dropping, right-aligned numbers, selected-row marker/background, compact viewport/search/sort status and access to full details on Enter.
5. Use short focus tabs and contextual hints; keep data and the selected control reachable in short/narrow frames. Show full instructions through the testing guide, not repeated paragraphs ahead of every table.
6. Preserve all request loading/filter/sort/detail/copy/trace-return, provider/account, savings scoping, nested trace/minimap and passive/explicit-paid judge workflows. Missing, zero, loading, error and stale observations remain different states.
7. Add only metrics derived from already returned real data. Preserve known-priced floors, unpriced counts, token categories, dimensional units, chronological axes and class/sample thresholds.

## Ownership

- Integration owner: shared feature presentation, band/table selection, core list/chart state, Overview/Projects/Activity, panel/chrome/footer, docs and final mounted review.
- Core analytics/request slice: Models/Costs/Tools and Requests/Errors/detail presentation; use shared presentation and list/chart contracts.
- Provider/savings slice: Providers/Gain metric cards, aligned tables, chart/legend details and focus presentation; keep independent reads and retained identity.
- Trace/passive slice: Traces/Frustration hierarchy, measured summaries, focus/selection, sparse/empty states; retain timing/history and paid confirmation safety.

## Acceptance and review loop

- At 100x40 and 160x45, a useful metric summary and the active data/graph appear without scrolling through instructions first.
- At 40x30, controls/caveats wrap intentionally; tables drop lower-priority columns rather than silently losing primary metrics; selected row/input stays reachable. No row exceeds its allocated width.
- Metric labels, values and hints have distinct weight. Graph values have units/formatting, UTC/local-day boundaries stay explicit, and null/gaps are not fabricated zeroes.
- Active pane and selected row are obvious without relying only on color. No repeated full-width rules inside the body; one intentional section gap.
- Populated, filtered-empty, truly empty, missing-account, failed-read, stale, detail and paid-confirmation states remain honest and navigable.
- Review actual mounted before/after surfaces, exercise the changed paths, fix observed visual/interaction defects, then review again. Test behavior/width/selection invariants, not source text or incidental wording.
- Run shared build/tests after edits settle, update testing/key documentation, and publish the UI changes. The original workflow PR #1 was merged during this work; the UI refinement is a follow-up PR on the same fork branch. Report only exercised platform/theme/external coverage.

## Implemented design

- Shared metric/table/focus grammar in `features/presentation.ts`, reusing `renderBands`. Production tables cap identity width, keep high-priority numeric columns, and mark selection with both background and a visible prefix.
- Shared production native-bucket plots in `charts/time-series.ts`, extracted from Providers/Gain rather than adding a third per-route convention. Formatted scales/legends, percent/cumulative/stacked modes, native window inspection and null gaps are supported; pure IR/probes remain separate.
- Metrics-first Overview/Models/Costs/Tools/Requests/Errors/Providers/Gain/Traces/Frustration layouts; scoped and loaded-population distinctions stay explicit. Projects retains unfiltered totals and shows one focused view; Activity retains its 371-local-day calendar.
- Compact route focus tabs, measured lists, viewport-only row formatting, real latest-observation initial chart selection, contextual hints and an active-centered narrow navigation strip.
- Request inspector sections and trace return, independently retained Errors panes, provider/account states, savings scoping, nested trace/minimap controls and explicit paid authorization are preserved.

## Mounted review and revision

Review used compiled omp 18.6.1 and Bun 1.4.2 on Linux arm64, first with linked real local history and then with an isolated recorded fixture. No paid model request or judge start was made.

1. Reviewed the baseline and first implementation across all twelve routes. Found crowded card hints, duplicated selected-point prose, oldest/quiet initial analytics inspection and rounded percentage ticks that repeated the same label.
2. Shortened cards/hints, removed duplicate details, selected the latest real bucket, formatted units/cost floors, widened native categorical bars and retained one-decimal percentage ticks. Re-reviewed all twelve routes at **100x40, 40x30 and 160x45**.
3. Narrow Requests still spent too much height on four long cards. Changed to six compact two-column metrics; the mounted 40-column frame now exposes five request rows. Literal `q[]` remains searchable; Ctrl+U and Enter clear/finish without closing or switching routes.
4. Reviewed light/Unicode, dark/ASCII and a custom-theme/Nerd surface. Actual custom ANSI foreground `(187, 102, 221)` appeared on the wire. Selected backgrounds, theme-native chart ink and preset fallbacks remained visible.
5. Deliberately removed standalone Bun from an isolated host PATH. The mounted error surface remained navigable and displayed no invented currency values. Replaced the long explanatory paragraph/repeated hint with a compact unavailable-state explanation and a **Read failed** badge rather than misleading **Cached** status; reviewed again at 100 and 40 columns.

Recorded fixture coverage: 612 requests, provider-account quota histories and exhausted readings, **1,734 saved tokens** with unknown original-byte reduction shown unavailable, blank trace-title fallback, nested root/child/grandchild traces, and passive frustration coverage. Trace minimap Home/Space/Right/Right/Enter changed a 63-second viewport to 6.3 seconds without losing event identity; child transcript navigation and Back worked. Quiet-day Activity details showed measured zeroes. The genuine missing-judge estimate error dismissed back to idle; it did not authorize work.

Ctrl+C checks restored zero overlays, the normal screen and a visible editor cursor on wide, narrow, custom-theme and failed-read surfaces. All smoke hosts were closed and their isolated workers reaped. Raw local-history frames were retained only as private review artifacts, not committed or published.
