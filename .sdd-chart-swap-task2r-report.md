# Task 2 rewrite report — host adapter on the real host pipeline

## Status: DONE

## What changed

`src/tui/charts/host-adapter.ts` was rewritten to call the host chart pipeline
for real. The previous commit (`e89d2be`) had shipped a **local** `HostChartSpec`
plus local `analyzeTable`/`planChart`/`buildChart`/`worthCharting` stand-ins,
because the pin was then `18.6.1` and `@oh-my-pi/pi-tui/charts/*` did not exist.
The pin is now `18.7.0` and the modules are present, so the stand-ins are gone.

- Deleted the local `HostChartSpec`, `TableAnalysis`, and the four stand-in
  functions. Static imports now come from the host:
  - `analyzeTable` from `@oh-my-pi/pi-tui/charts/table-data`
  - `planChart`, `buildChart`, `worthCharting`, and `type ChartSpec` from
    `@oh-my-pi/pi-tui/charts/chart-plan`
- `TimelineChartSpec = ChartSpec & { stacked?; cumulative? }` replaces the old
  bespoke spec; stacked/cumulative are still **recorded, not rendered** (see
  below).
- `planTimeline` and `planSeries` build the host table with the pre-flight
  ruling: `header = [labelCol, ...measureNames]`, rows = categories × measures
  (column 0 = categories). `planTimeline` labels its bucket column with an ISO
  timestamp so the host types it `temporal` (a real line axis); `planSeries`
  uses `Bucket N` labels.
- `renderHostChart` redraws host `ChartSpec` geometry through `renderSeriesChart`
  (our glyphs + `resolveSeries`), and formats every `dim === "currency"` series'
  labels through `costWithUnpriced` — never host `formatValue`.

## Money honesty

Cost cells are written with a `$` mark so the host types the column `currency`
(`dim: "currency"`), but the RENDERED label is always `costWithUnpriced`. A cost
of `0` with `unpriced > 0` renders `N/A`, not `$0`. Pinned by the
`adapter never calls host formatValue for currency` test, which now also asserts
`spec.series[0].dim === "currency"` (the host actually typed it, rather than a
local heuristic).

## Gap policy

`worthCharting` is the host's real gate (≥4 categories, and either ≥9 plotted
values or a ≥3× spread). `planTimeline`/`planSeries` return `undefined` whenever
`planChart` finds nothing or `worthCharting` rejects. Two tests cover this:
- 2 buckets → `planChart` returns undefined.
- 4 buckets at a 2× spread (`[1,1,1,2]`) → passes `planChart` as `line`, then
  `worthCharting` rejects → adapter returns `undefined`.

## Stacked / cumulative

Still recorded on the spec (`TimelineChartSpec.stacked`/`.cumulative`) and not
applied: `renderSeriesChart` has no stacking geometry, so a `stacked` spec draws
as its component bands. Documented on `TimelineChartSpec`.

## Tests

`test/chart-primitives.test.ts`:
1. `planTimeline returns a ChartSpec for valid timeline data` — 4 buckets,
   `kind === "line"`, 4 categories, 1 series. (Updated from 3 buckets: the host
   needs ≥4 categories for a line, and 3 buckets are rejected by `worthCharting`.)
2. `adapter never calls host formatValue for currency` — asserts the host typed
   the column `currency` and the render contains `N/A`, not `$0`.
3. `planTimeline returns undefined for sub-threshold data` — 2 buckets.
4. `planTimeline applies the worthCharting gap policy` — 4 buckets, low spread.

Only test 1's fixtures changed (bucket count); the assertion shapes are the
same. No test asserted the deleted local-spec shape.

## Concerns

- The host's `worthCharting` is stricter than the old local gate (`series.length > 0`).
  Callers in Task 3/4 (`renderTimeSeries`, `barRows`) must handle `undefined`
  and render their own empty-state line, as the plan's Task 3 snippet does.
- `planSeries` collapses its own axes: the host's `planChart` may pick `paired`
  or `grouped` for multi-series bar tables, so `renderHostChart` for a
  multi-series `planSeries` spec will band more than one series. That is the
  host's decision and is the intended behaviour of the swap.
